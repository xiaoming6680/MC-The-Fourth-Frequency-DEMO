# 世界接口终局

`1.0.0-rc.6` 末地终局的规则手册：进入条件、仪式、状态机、数值、八类行动、两种结局与 F8。

本文只写**规则是什么**。每条规则背后的取舍、它修掉的 BUG 和被否决的方案，都在[设计札记](design-notes.md#世界接口终局)。

> 旧版「七分钟、360 基础生命、热栏重排、768 格侵蚀」与主世界旧祭坛已退休，不再适用。

## 进入终局前

终端主线按服务端目标推进，完成即发奖励，无需领取：

| # | 目标 | 说明 |
| ---: | --- | --- |
| 1 | 认识终端 | 点过四个标签页；新档由开机引导带着走（工具 → 记录 → 文件 → 主页），走的是与手动点击完全相同的服务端路径 |
| 2 | 12 份原木／木板 + 6 份铁 | 不随人数缩放 |
| 3 | 下界 → 下界要塞 → 烈焰棒 → 返回主世界 | **烈焰棒随人数下调**：单人 3 根，两人及以上 2 根。「找到要塞」按脚下是否为要塞结构部件判定，与导航工具同一个测试；烈焰棒达标时补记该里程碑 |
| 4 | 3 次末影之眼投掷记录 | **定位全队共享**：任一人攒够三次，坐标与三角测量顶点复制给其余在线绑定玩家。个人次数仍照记 |
| 5 | 找到要塞并进入末地 | |
| 6 | 击败世界接口 | |

**个人追逐不是门槛。** 未完成的追逐不会阻止进入终局，也不会在末地补发。

**从召唤第一 Tick 到结算，普通异象、空档补压与正式追逐全部暂停**，已在跑的就地中断。停摆按玩家判定：名单成员与身处末地的任何人停摆，其余人照常。规则见[异象、终端形态与个人追逐](anomalies-and-pursuits.md)。

**战斗期间只有战斗自己的声音上提示栈。** 普通进度提示留在队列里按原 TTL 过期；被拒绝的操作（`TONE_DENIED`）仍照常回话。判据是纯函数 `TerminalNoticePayload.surfacesDuringEncounter`。

建议在放入最后一只眼前备份存档：终局会留下永久末地伤痕，结局还会给当前本地存档建立隔离标记。

## 场地

- 战斗在**原生末地主岛**，不生成人工平台。贴地放置 11×11 祭坛与 10 座稳定锚。
- 20 个折跃门槽位仍保留在协议与状态里（`MAX_GATEWAYS = 20`），但**不再放置任何方块**；旧存档的基岩门框会被拆除。
- **第 12 颗眼落框会永久取代原版末地结局**：出口传送门、龙蛋与末地折跃门不再生成，末影龙无法复活。共享服上外岛、鞘翅与末地城因此永久不可达。服主提示见[世界观圣经](world-bible.md)。
- 祭坛中心与原版返回区域有保护半径；基岩、黑曜石柱、末地传送结构、方块实体、关键 MOD 方块及免疫标签不会被战斗改写。
- **侵蚀只作用于末地石**，服务端与客户端同一条规则。柱子保留自己的材质，玩家靠它们认方向。
- 激光提前 90 Tick 警告，单条扫射排队擦伤上限 160 格。
- 祭坛建造会**跳过已含方块实体的格子**并记日志：宁可缺一块墙，也不吞掉别人的箱子。

### 末地的雨

**末地会下雨、会打雷、没有云。** 这是纯客户端呈现，整个末地都如此，不专属于这场战斗。

| 项 | 值 |
| --- | --- |
| 末影人 | **不存在**（`EndPopulationService`）。末地是这个 MOD 的最后一幕，那里唯一该动的东西是遭遇战本身：末影人是唯一会瞬移的怪（出现时没人看见它来），是唯一对"被看"有反应的怪（整座岛变成一个不能对视的地方），而在终局里它们就是一堆和演出撞色的紫色粒子。做法是**加载即移除**而不是禁止生成——实体也会通过传送门、指令、旧存档区块和龙战折跃门进来，一条规则覆盖全部，且完全可逆（移除 MOD 后末地自己长回来）。只认 `minecraft:the_end`，镜像维度和未渲染层不动。**代价**：末地不再掉末影珍珠 |
| 雨量 | 在 0.45–0.65 之间起伏，周期 1100 Tick；相邻 Tick 变化 < 0.005 |
| 雷声 | 按世界时钟切 600 Tick 的槽，每槽独立决定；平均约 40 秒一次，最短间隔 ≥ 80 Tick，音高逐槽散开，方位全场共享 |
| 云 | 恒无（断言 `EnvironmentAttributes.CLOUD_COLOR` 的 alpha 为 0） |
| 存档影响 | **零**。不写 `ServerLevelData`，`EndWeatherContractTest` 扫描全部源码守住 |
| 规则影响 | **零**。`isRaining()` 在末地永远为假，客户端 GameTest 反向断言 |
| 击败后 | **雨在 200 Tick 内淡出到 0 并不再打雷**（`CLEAR_FADE_OUT_TICKS`）。只认成功（`Outcome.SUCCESS`）：失败那条路上世界正在崩塌，那片天不是玩家挣来的。赢完离开再回来的人直接看到已经放晴的天，而不是再淡出一次 |

## 终端托管仪式

服务器权威的集体事务：

1. **手持**自己的有效绑定终端右键共振核心即加入名单，上限 8 人。背包里有但没拿在手上不算；空手右键仍可打开界面查看名单。
2. 第一台终端进核心时开始 3 分钟窗口。后来者加入的是**同一个**窗口，不会延长它。
3. 插入成功后**祭坛界面自动弹到插入者面前**，带着这次插入自己的状态行。召唤是手动的一步，而插入是唯一保证玩家站在核心前的时刻——不自动打开，玩家面对的就是一个刚拿走终端然后不再有任何反应的方块。
4. 同一时刻，**末地里的其他人（含旁观者）都会收到一条通告**：谁交了、祭坛现在握着几台、要开始还得有人按召唤。名单只存在于界面里，界面又只有一个人开着。
5. 窗口内可随时撤回自己的终端，终端按账本返还。**「中止仪式」按钮已从界面移除**：撤回自己的那一台仍在，而一键把别人的托管一起推翻不再是界面上的一个按钮。服务端 `cancel()` 事务与 `CANCEL` 协议值保留，用于回滚与旧客户端。
6. **召唤是一次显式的按住**，只有已交出终端的人能按，且在场已加入者必须全部完成托管。界面上它是**居中的大号自绘面板**，不是原版按钮：可按时脉冲（周期 1.6 秒，远低于 3 Hz 上限）、悬停变白，不可按时整块转灰。**按下只是把它推到行程起点**——面板从左往右填满约 1.2 秒（`ending/SummonHoldPolicy`，纯类，`SummonHoldPolicyTest` 直测），填满才原子提交；中途松手清零、**不发任何请求**。行程只是演出：填满后发出的仍是原来那条请求，服务端的名单、阶段、托管与原子性校验一字未改。
7. 三分钟内无人召唤则窗口失效：全部终端原路返还，祭坛回到休眠，可立刻重来，无惩罚。
8. 服务器重载后的不确定状态或任一校验失败同样回滚并返还。

第 9 个人只被单独拒绝（`roster_full`），不影响另外八个位置；别人上下线与仪式无关。终端在战斗期间由系统保管，成功、失败与安全恢复都走恢复账本。

## 三个形态的武器差异

形态之间原本只差生命、体积、伤害和出手频率，**两把武器本身完全一样**——同一个天锚落在同一个圈里、同一条激光按同一个速率扫。于是升级只是算术，第三阶段读起来像血条更短的第一阶段。现在这两把玩家全程都在读的武器会随形态变形（`WorldInterfacePhasePressure`，纯类）：

| | 一形态 | 二形态 | 三形态 |
| --- | ---: | ---: | ---: |
| 天锚半径 | 3.6 | 6.48 | 10.44 |
| 激光伤害间隔 | 5 Tick | 3 Tick | 3 Tick |
| 激光灼痕间隔 | 2 Tick | 1 Tick | 1 Tick |
| 激光追踪滞后 | 10 Tick | 6 Tick | 6 Tick |
| 激光粗细与灼烧半径 | ×1.0（2.2 格） | ×1.45（3.19 格） | ×1.9（4.18 格） |
| 同时发射的光束 | 1 条 | 1 条 | **2 条**，绕瞄点各偏 6° |

**一形态原封不动**——它是整场战斗调参的基准，也是教会这两把武器的那一段，上表第一列全部返回旧常量。

**追踪滞后是这里唯一一条削弱玩家的数字。** 10 Tick 的跑动约 2.5 格，明显大于光束 2.2 格的灼烧半径，那点余量就是「跑得掉」的全部来源；6 Tick 只有约 1.5 格，小于灼烧半径——从二形态起直线跑不再能甩开光束，必须转向。

**光束的画法和烧法用同一个系数。** 渲染器把每层壳的宽度乘 `beamScale`，服务端把灼烧半径乘同一个数——看得见的边必须就是危险的边，否则玩家会站在"看起来在光束里"的地方却什么都不掉，或者反过来。客户端追踪滞后也改成按形态取（之前写死协议常量，导致二形态起画出来的光束和真正烧人的光束差了四个 Tick 的距离，这是个真 bug）。

**三形态的两条光束绕瞄点对称张开约 12°。** 中间那道缝是能站人的地方——这正是"分成两条"是升级而不是"更宽的必中条"的原因。天锚半径上限有单测守着：最宽的那个圈仍必须能在自己的 90 Tick 预告里跑出去。

**锁定读数从来没被拿掉。** 曾经短暂地对三形态的两把武器隐藏过，理由是"失去倒计时本身就是升级"；2026-08-29 按用户要求撤销了——在两条光束加一个直径二十格的天锚圈同时上屏的那个时间点，十字线读数是玩家判断"哪个是冲我来的"的唯一依据。

**三形态的第二条攻击线现在会开出这两把武器。** `VOLLEY_ACTIONS` 原本只有能量弹和触肢，所以额外那条线只增加压力、从不增加**需要分别读的东西**。现在天锚和激光都在池子里：天锚可以叠（几个圈同时在岛上张开正是三形态的样子，每个圈都仍然是「站开就行」），**激光不叠**——一条扫射光束已经覆盖全岛并画在每个人屏幕上，两条不是两倍威胁，是一帧读不了的画面。已有一条时（含调度线那条）齐射会把它换成能量弹。

## 战斗演出

粒子在这一段是**故意不省的**（用户 2026-08-29 明确要求），`WorldInterfaceVfx` 的类注释里写明了这一点。

**用的不是药水粒子。** 第一版把紫色一律画成染色的 `ENTITY_EFFECT`，那是游戏里最小最平的一种粒子，也是玩家十年来训练自己忽略的那一种——六十个环用它画出来只是一团雾。现在紫色是 `WITCH`（同色但大好几倍、有形状，五十格外仍读得出），高热的核心是 `SOUL_FIRE_FLAME`（自带拖尾，所以环是**转过去的**、螺旋是**在走的**），符文是 `ENCHANT`。三个高层图元把它们组合起来：**法阵**（`runeCircle`：外圈符文 + 中圈光 + 向心写入的符文 + 放射刻线，三层套起来才读得出是「被画出来的图」而不是一个圈）、**爆炸**（`detonation`：`FLASH` + `SONIC_BOOM` + 多个 `EXPLOSION_EMITTER` + 烟花壳 + 火焰壳 + 多重外扩环 + 放射裂纹，按传播距离分层）、**光柱**（`beacon`：火焰芯 + 两股反向缠绕的螺旋 + 两端环箍）。`SONIC_BOOM` 一次只发一个——它是一个巨大的白色环形冲击，两个叠在一起就是一团读不了的白。它只提供形状，不持有状态、不掷随机数、不碰权威：环、任意轴向环、外扩冲击环、螺旋、折线电弧、球壳、光柱、放射条，相位一律取自世界时钟，所以每个客户端画的是同一帧，重启也接得上。全部经 `ArenaParticles`（512 格）发出——场地 160 格宽，原版 32 格的粒子限制会把大半效果藏掉。

| 位置 | 加了什么 |
| --- | --- |
| 本体常驻（`emitBossPresence`，改为**每 Tick**） | 三层互不共面、成对反向自转的陀螺环；核心按血量加快的球壳脉冲；**地面足迹**；头与核心之间的电弧和头部环箍 |
| 命中本体 | 沿法线贴在被打中那一点的环 + 球壳，外加一条从伤口打回核心的电弧 |
| 形态切换 | 起手 12 Tick 的**吸入**（地面环内收、光柱上行）；爬升全程的螺旋尾迹与环；`MORPH_REVEAL_TICKS` 那一帧的三层球壳 + 四道倾斜环；落地的三重外扩冲击环 + 放射条 + 光柱 |
| 激光 | 出膛时三道横跨射线的环 + 球壳 + 已经缠好的螺旋；扫射期间双股螺旋沿轴推进，每 3 Tick 甩出 3 条侧向电弧；接地点加外扩环与放射条 |
| 天矛 | 柱体由三股螺旋绕成、领口环跟着下落前沿；落点三重冲击环 + 10 条放射裂纹 + 球壳 |
| 触肢鞭击 | 落点放射裂纹 + 冲击环 + 球壳 |
| 能量球 | 飞行每 Tick 绕步长缠螺旋、横向环标出到达位置；爆炸球壳，命中时再加三重冲击环与放射裂纹 |
| 锁定提示 | **每种攻击一个几何形状，全部画在脚下**（详见下表） |
| 触肢下落 | 预告期间从本体核心到落点画一条缠绕的轨迹 + 电弧。这一招不发射任何东西——打你的是本体自己的触手，三形态时它从十八格高的三十三格宽的躯体上垂下来，站在地面的人根本分不清那是什么，只经历"地上出现一个圈，然后被不明物体弹飞" |
| 地面标记 | 外圈之外加一道随读秒收拢的内圈和连接两者的放射条：原来只说了「在哪」，没说「还剩多久」 |

### 地面足迹刻意不是法阵

本体悬空，所以它正下方的地面画着一个足迹标记，否则八个人在 160 格的岛上抬头都找不到它。它曾经也是法阵，那是个错误：**天锚的落点标记也是法阵**，于是地上同时存在两个紫色的圆形符文图，一个意思是"它在你头顶"，另一个意思是"这里马上要被砸"，玩家得一边跑一边分辨。

现在足迹换了一套语言：**白色、直边、六边形、没有符文**（外六边形 + 内六边形 + 中心十字），而所有的攻击预告都是圆的。一眼就分得开，且大小随形态变化，所以足迹同时说明头顶是哪一形态。

### 锁定提示：一种攻击一个形状

原来六种攻击共用同一个收拢的圆环，玩家在打的时候不会停下来读标签写的是什么，只看到"一个锁定"，然后要猜答案是跑、是抬头、还是不用动。上一版试图用**穿过玩家身体的竖直笼环**解决，那更糟：视角高度的绑定粒子会挡住玩家读战场的那部分屏幕，一个遮住自己所警告之物的提示是负收益。

所以形状承担含义，**并且一律平铺在脚下**：

| 攻击 | 地面图形 | 为什么 |
| --- | --- | --- |
| 激光扫射 | 环 + 4 条指回核心的放射线 | 它沿一条线从核心过来，所以它的标记有方向 |
| 天锚 | 环 + 一道从上方降下来的环 | 唯一从正上方落下的攻击，所以唯一一个向上伸 |
| 触肢鞭击 | **旋转的三角形** | 三条触手，三条边 |
| 武器扣押 | **方形** + 向内收的箭头 | 没有东西飞过来，是东西被拿走；方形因为它伸手要的是物品栏 |
| 快捷栏清空 | **九颗珠子** + 方形 | 九个格子 |
| 抓取投掷 | 只有向内急收的箭头，边缘什么都没有 | 它伸进来把人拎走 |

只有最后 40% 的读秒会在**头顶 3.1 格**多画一道环——高于视线，不挡战场。抓取期间的"笼子"同理：脚下一环、头顶一环，不再穿脸。

### 快捷栏清空的掉落物

`GAZE_HOTBAR_CLEAR` 把九格物品按九个方位甩出去，落在末地石上、在战斗中、在击退把人推开之后——可回收但实际上找不到。`WorldInterfaceDropBeaconService` 给每个掉落物**立一根光柱**：末端棒的柱身（3.6 格）、紫色顶帽、脚下一圈紫环，每 2 Tick 重画一次，同样走 512 格发送。

拾取延迟、despawn、掉落规则一概不动——加的只是「看得见它在哪」。物品实体消失（被捡、被烧、超时）即刻销号，上限 256 条、单条最长 6100 Tick，服务器停机全清，不落盘。

## 单向生命周期

`UNPREPARED` 是正式终局前的哨兵，后续十个阶段按 wire ID 单向推进：

| wire | 阶段 | 含义 |
| ---: | --- | --- |
| 0 | `UNPREPARED` | 尚未准备终局 |
| 1 | `ARENA_READY` | 场地就绪 |
| 2 | `WAITING_TERMINALS` | 收集终端，等待召唤 |
| 3 | `SUMMONING` | 托管已提交 |
| 4 | `PHASE_1` | 生命 `>70%` |
| 5 | `PHASE_2` | 生命 `>35%` |
| 6 | `PHASE_3` | 生命 `≤35%` |
| 7 | `SUCCESS_RESOLUTION` | 超时前受到致命伤 |
| 8 | `FAILURE_RESOLUTION` | 崩塌先达 100% |
| 9 | `PORTAL_OPEN` | 3×3 出口开放 |
| 10 | `COMPLETE` | 诗篇／返程已确认 |

生命回复不能让形态倒退。**同 Tick 先判崩塌再判致命伤**，所以临界时刻以失败为准。

## 本体几何

**本体在天上飞，头伸下来给玩家打。** 玩家在地面能打到的是它垂下来的部分。

| 量（一／二／三形态） | 值 |
| --- | --- |
| 本体绘制下缘离地 | 8 / 14 / 18 格 |
| 下颌在整段动画中的离地余量 | 1.69 / 1.12 / 0.72 格 |
| 中央头判定框下沿离地 | 2.16 / 2.12 / 2.25 格（远在 4.5 格挥砍内） |
| 本体前缘离玩家 | 4.77 / 6.77 / 7.65 格 |
| 头判定面离玩家 | 1.00 格（按构造） |
| 碰撞箱高 | 约 12 / 23 / 32 格 |
| 可攻击部件数 | 14 / 16 / 20（本体、三头、每条脖子 2 段、每条绘制触手 1 段） |

- 净空按「玩家脚下到**绘制**本体下缘」表述；实体原点由 `combatHoverHeight = 净空 − massBottomLift` 反推，`massBottomLift` 量到模型真实最低壳体。
- **模型在 Blockbench 里编辑。** 编辑源是 `docs/art/world_interface/world_interface.bbmodel`，`tools/export_world_interface_model.py` 把它导出为客户端烘焙的几何 JSON；骨架骨骼的枢轴与绑定旋转必须与 `WorldInterfaceRig.bindPose()` 一致，`WorldInterfaceGeometryContractTest` 逐轴比对。管线细节见[美术与资产管线](art-pipeline.md)。
- **判定框绑在动画后的骨骼上。** `WorldInterfaceRig` 每 Tick 摆一次骨架（绑定姿势 + 剪辑 + 程序化漂移 + 结构下垂），服务端据此放框、客户端用**同一次求值**驱动 `ModelPart`，剪辑数据在 common 的 `WorldInterfaceClips`。
- 头部判定框锚在**下颌**（`+1.45`）而不是颅骨中心，判定余量 45%（`HEAD_HIT_SLACK`）。头顶那对角刻意不纳入。
- 姿势时钟走同步的 `POSE_TICK`（每 20 Tick 重发，客户端闩存偏移自行计数），否则两端相差 5 Tick、头与判定框差 0.464 格。`WorldInterfaceClientGameTest` 按 0.20 格封顶守住。
- **头部注视**：服务端每 Tick 写入相对本体朝向的方位与俯仰（`GAZE_YAW / GAZE_PITCH`），两侧头按 0.72 权重跟随，偏航与俯仰上限各 **60°**，超出即钳制。渲染按 partialTick 插值，判定框不插值。
- **触手**判定柱只覆盖绘制出的最后一节，末端停在本体下方 4–7 格；触手不是地面近战目标。
- 形态切换的收缩演出（最多缩到 28%）走 `renderScale`，判定框跟着缩。

### 高空窗口

`WorldInterfaceSkyholdPolicy` 是唯一事实源，纯类、无持久化。

| 项 | 值 |
| --- | --- |
| 周期 | 900 Tick（45 秒） |
| 抬升段 | 末尾 260 Tick（13 秒），高出战斗站位 26 格 |
| 爬升／下降 | 两端各 50 Tick 平滑曲线 |
| 生效形态 | 二、三形态；第一形态**永不抬升** |
| 抬升占比 | 28.9%（完全够不着的顶点段 17.8%），硬性上限 40% |
| 抬升时本体下缘 | 40 / 44 格，只有弓弩三叉戟够得到 |
| 速度 | `CLIMB_SPEED` 0.70、`CHASE_SPEED` 0.11 格/Tick |

- 抬升期间照常出手，**唯一被排除的是抓取投掷**（`canStartWhileAloft`）。
- 爬升起始 Tick 播 `world_interface_flight` 并配一声低吼。
- 一个阶段的第 0 Tick 永远在站位上。
- **站位是「最近只到这么近」**，不是设定点：只在距离大于站位时才逼近，进入后水平方向原地不动。
- 站位由头解算：`站位 = 头前伸 + 头判定半径 + 1 格`（`WorldInterfaceAnatomy.combatStandoff`）。颈链前倾 `-0.34 / -0.29`，头前伸 4.6 / 9.7 / 14.0 格。
- **召唤下落停在站位之上 12 格**（`SUMMON_ARRIVAL_LIFT`）并悬停，由追击带下来。

### 形态切换

第二、三形态的 morph 共 80 Tick（4 秒），本体**离开竞技场**：前 12 Tick 原地下蹲蓄势 → 加速爬升到地面之上 110 格 → 在 40 Tick 顶点切换形态 → 后 40 Tick 减速落回新形态站位（含当时的高空抬升量）。位置由 `snapTo` 写死而非给速度，两端一致、存档中途可续。离场与落地各发一次冲击环，落地补一声吼。

## 稳定锚

存活锚会治疗并重构外壳、延长攻击间隔，并在柱脚投射半径 8 格、不受高度限制的稳定区。区内玩家受到的伤害降低 20%，战斗擦伤与失败侵蚀不能修改区内地形。世界接口自身**不能**摧毁稳定锚。

| 已拆 | 目标承伤 | 冷却系数 | 存活锚合计回血 | 稳定区数 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 60% | 1.15 | 每秒 0.20% 最大生命 | 10 |
| 5 | 80% | 1.00 | 每秒 0.10% 最大生命 | 5 |
| 10 | 100% | 0.85 | 0 | 0 |

每拆一座：承伤 +4 个百分点、停一份回血、冷却系数 −0.03、对应稳定区熄灭。Boss 基础移速固定 0.11，不随拆锚变化。**拆锚不影响崩塌计时。**

**拆锚是取舍，不是「先拆塔」**：收益是更快压低血池，代价是更密的攻击与更少的安全地面。战斗中第一次对锚的正伤害玩家攻击即摧毁它；零伤害、非玩家、旁观者及非战斗阶段来源不能拆锚。每次拆除在 HUD 上播约 60 Tick 金光并把锚标签替换为「承伤增加 · 出手更密」——这行字直接说后果，因为它是终局里唯一可操作的战术信息，而首次打到这里的玩家没有余地去解读一组箭头。

成功进入终末之诗时服务端提交最终拆锚数，客户端据此选择「全数保全 / 部分拆除 / 全数拆除」三种成功叙述。

### 锚的形态与破坏演出

锚是 MOD 自己的实体（`StabilityAnchorEntity`），约 1.75×2.75 格的四向夹具，没有头也没有脸：四套同构夹爪以 90° 分布，经上臂、方形转轴、前臂、腕轴、下扣脚爪五级向上外张再向下收拢，扣住柱顶那一格基岩帽。躯干围一枚白金色胸腔核心；顶部是一枚裸露的中继核，四周留空以便牵引束在水平 360° 与大俯仰角内离开。四枚校准瓣低于中继核赤道且彼此断开。发光只限两枚核心与关节金缝。

拆锚是权威事件，命中当 Tick 即退出存活掩码、停止治疗与稳定场、失去碰撞；之后 16 Tick 只是几何在解体：

1. 中继核当场引爆（`EXPLOSION_EMITTER` + 近距爆炸粒子）；
2. 三圈爆轰波沿基岩帽向外阶梯展开；
3. 放掉一直握着的那束光，沿垂直方向射出光柱（与召唤演出十座锚依次点火同一形状）；
4. 半径 26 格冲击环离开柱脚；
5. 声音两层：原版爆炸叠 `world_interface_anchor` 本嗓（音高 0.62）；
6. 客户端前两拍把碎片**向外**抛，之后接回向内内爆与紫色余烬。单锚粒子上限 100、单 Tick 24，十座合计仍在 1024 封顶内。
7. 相机由服务端在中继核发 `WorldInterfaceBlastS2C`，HEAVY 档、80 格衰减——谁动的手谁震得最厉害。

演出全程不调用世界爆炸、不改写方块、不生成火与掉落物；断线或重启时残留视觉直接清理。

**形态缩放**：伤害 `formDamage = 1 + 形态 × 0.15`（1.00 / 1.15 / 1.30），天降光束半径 `formRadius = 1 + 形态 × 0.22`（1.00 / 1.22 / 1.44），落点擦伤半径 +1、上限 +50%。**激光灼烧半径与触手抽击半径不缩放。**

**排程节奏**：一阶段 150–200 Tick、二阶段 75–105、三阶段 35–60，严格单调。第三阶段另开**齐发**通道，每 40 Tick 追加若干行动，只投放龙息弹与触手抽击。齐发不写存档信封。

**随人数收紧**：排程间隔乘 `1 / (1 + 0.18 × (人数 − 1))`，下限 0.45；齐发每次 `1 + 0..1 + (人数−1)/3` 个、并发上限 `3 + (人数−1)/2`。**单人局两个系数恰为 1.0 与 3。** 排程间隔不得低于 `MIN_SCALED_INTERVAL_TICKS = 20`。

**排程必须在选定行动之前排除选不出目标的候选**（`continue` 而不是选中后放弃）。`WorldInterfaceActionSchedulerTest.everyPhaseKeepsAnActionThatNeedsNoExclusiveControl` 守住「任何阶段都不能只解锁强控制」。

**强控制**：抓取投掷、扣押、清栏、强制驱逐互斥共用一条通道；同一玩家在一次强控结束后有 600 Tick 保护。退休的「抓取砸落」wire id 3 永久空置，不改派。

## 多人目标分配

- **攻击只落在冻结名单里的人身上。** 本体的垂直跟随与三头注视同样只跟名单内的人。范围伤害仍会打到站在爆炸里的任何人。
- **重生覆盖按冻结名单写入**（在 `commitSacrifice` 之后），名单成员中途登录由 Tick 补写。
- 排程与齐发共享一份**瞬态注意力账本**：
  - 上一次被点名的玩家在下一次选择中被硬性排除（只要还有别人可选）；
  - 权重 `1 / (1 + 600 Tick 窗口内被点次数)`；
  - 齐发避开排程正在锁定的人与同批已分配的人，候选耗尽才允许重复；
  - **全体性行动不占名额**（判据 `singlesSomebodyOut`：目标数严格小于场上人数）。
- **本体站位跟整桌人**：`1 / (1 + 距离)` 加权重心（`attentionCentroid`），单人时恰好收敛到该玩家。垂直跟随仍只看最近的玩家；三头**注视**也仍跟最近的玩家。

## 锁定提示

除强制驱逐外，每种带锁定的行动在锁定期同时给出三层提示：全屏边框与倒计时条、脚下收拢的粒子环、锁定音。**锁定窗口本身不造成伤害。**

- **只有真正的锁定类行动用锁定音**（`isTargetingLock`：激光、龙息弹、天矛、抓取、抽击）——它们都是带着你的坐标飞过来的东西。
- **武器扣押与凝视清栏不是锁定**，用相反的形状：`NOTE_BLOCK_BASS` 低音，固定 9 Tick 间隔，音高 0.95 → 0.55，不加速、不收束。
- 锁定音用 `NOTE_BLOCK_BIT`：搜索阶段间隔 11 Tick，随窗口收到 3 Tick、音高 1.32 → 1.74、音量 0.26 → 0.42；越过 `LOCK_COMMIT_FRACTION`（70%）转为 2 Tick 一响的定音（音高 2.0、音量 0.52）。刻意用 UI 音而不是定位音。
- **进度条只负责进度**，不画刻度。越过 70% 时准星下方文案变成 **`! 被锁定 !`** 并转强调色；这句话只对锁定类行动出现。

## 相机震动

服务端在爆炸发生处发 `WorldInterfaceBlastS2C`（坐标 + 半径 + 档位），**衰减在客户端算**；落点在半径之外的玩家不发包。节流规则是纯函数 `WorldInterfaceBlastService.permits`。

| 来源 | 档位 | 半径 |
| --- | --- | --- |
| 激光落点（每 6 Tick） | MEDIUM | 42 |
| 天降光束落地 | HEAVY | 72 |
| 龙息弹起爆 | 一形态 MEDIUM，二三形态 HEAVY | 伤害半径 × 7 |
| 触手落地 | MEDIUM | 34 |
| 稳定锚破坏 | HEAVY | 80 |
| 冲击环 | ≥42 为 HEAVY，否则 MEDIUM | 环半径 × 1.35 |

冲击环**封顶在 HEAVY**。天矛在被瞄准玩家身上的冻帧仍在客户端，触发 Tick 与服务端落点同一 Tick。

## 粒子与音频

- **本体自己的天气**（`emitBossPresence`）：核心日冕、轮廓上按体型放大的场、身下落灰、二形态起三头之间的电弧。由世界时钟纯函数推导，**无随机、无状态**，唯一携带的信息是血量。预算约每 Tick 三次发射。
- **每一招都有「开火」那一帧**：激光在 90 Tick 预警期间同步 `chargeCore` 并在开火帧给枪口演出；天矛在蓄力后半段自上而下填充光柱；触手落地在**击退实际生效的半径**上抛一整圈粒子。
- **激光类命中叠色散后处理**（`world_interface_dispersion` / `_far`，12 Tick），挂在**到达帧**上，与伤害结算、震屏包同一 Tick。滤镜语言见[异象、终端形态与个人追逐](anomalies-and-pursuits.md#三套滤镜语言模拟信号-vs-数字损坏-vs-色散)。
- **远处粒子必须显式放宽发送半径**：`sendParticles` 默认只发 32 格内。本体风暴、聚能、枪口、光束光粒与天矛光柱走 `ArenaParticles`（512 格）；地面标记、落点爆发与锁定环仍走默认。
- **混音余量**：`AudioService.ENCOUNTER_MIX_TRIM = 0.72`，作用在服务端 `playBounded`、客户端 `playBoundedLocal` 与形态环境床 `AmbientLoop` 的每 Tick 增益上，由 `EncounterMixTrimTest` 断言三处都乘了它。借用原版的那一族（`playWithReach`：龙吼、凋零嗓、原版爆炸）改用**射程**压：`BLAST_REACH_BLOCKS` 96 → 72，吼叫保留 96。
- **吼叫是叠加音**：`ENDER_DRAGON_GROWL`（音高 0.82 / 0.68 / 0.56）与 `WITHER_AMBIENT`（0.68 / 0.56 / 0.46，音量 62%）同点同 Tick 发出，分开变调约四度。
- **节流**：受击音 4 Tick、激光落点音效与震屏 6 Tick、触手前摇滴答 8 Tick。地形擦伤与粒子不节流。

> 自动化能锁住排程不变式、伤害事务与声音资源契约，但「连续打三分钟仍每招可听」仍属真实客户端人工验收。

## 成功结算的顺序

每一拍都等上一拍**看得见地结束**之后才开始，不重叠。计时从 `SUCCESS_RESOLUTION` 起算：

| Tick | 事件 |
| ---: | --- |
| 0 | 播 `SUCCESS_COLLAPSE` + `SUCCESS_FADE`（各 9 秒）；同 Tick 发死亡音、成功音与第一声龙吼，核心炸出冲击环（半径 = 体半宽 × 2.5） |

死亡剪辑分工：`SUCCESS_COLLAPSE` 管躯体与十条触手（躯体只有「停止维持水平」的偏移，最终 −22° 俯仰、54° 偏航，先胀到 1.14 再塌到 0.02；触手按 `1.9 + 序号 × 0.36` 秒依次松脱，**与服务端 `emitLimbFailure` 用同一份时刻表**）；`SUCCESS_FADE` 管光与环，顺序即含义：眼先闪一下再灭 → 颚失去支撑张开 → 环最后脱离本体上浮 52 单位、转 2160° 后散掉。

召唤演出**不写任何存档状态**，全部由结算时钟推导，重启可续、中途加入的客户端也能接上。失败结算不受影响，仍是完整的 260 Tick 逃逸演出。

**末影龙的飞行**：轨道角度是累积量而非世界时钟推导；原版飞行积分被 `EnderDragonMixin` 从这条龙身上摘掉（服务端在 `START_SERVER_TICK` 写位置，`aiStep` 结尾那次 `move` 被重定向）；下降进度只吃龙自己的年龄，不由阶段推导；朝向取**这一 Tick 实际走过的位移**而非圆周切线。`FriendlyDragonServiceTest` 断言相邻 Tick 位移永远小于 4 格。

### 胜利之后崩坏条倒放

结算开始后 `repairProjectedElapsedTicks` 把下发给客户端的崩坏计时按 `repairFraction` 逐 Tick 往回绕，`REPAIR_DURATION_TICKS = 500`（25 秒）。同一个分数驱动三件事：HUD 崩坏条倒退、末地石材质侵蚀抬起、地面修复从祭坛向外扫开。

**权威计时不动**，被改的只是投影。判据是 `repairsCollapseReadout(stage, succeeded)`——结算及其之后的所有阶段都保持倒放，`repairFraction` 封顶在 1。

## 出口与诗篇

成功或失败结算完成后，祭坛中心开放 3×3 出口。进入后沿用原版流程：

`showEndCredits → WinScreen → 自定义分支诗篇 / 制作人员名单 / 片尾资源 → PERFORM_RESPAWN`

MOD 不伪造第二套重生系统；原始出生点由账本保存并恢复。成功诗篇确认且玩家真正回到主世界后，视距才从结局前的按维度锁定（6/12/16，其他维度 12）永久解锁为 16。

- **`PORTAL_OPEN` 只等当下在线的人。** 离线成员的诗篇与重生点条目原样留在账本里，下次登录时 `reconcilePlayer` 送他回主世界并还原重生点，`startPoem` 补上欠他的诗篇。另有兜底：结算起 20 分钟后无条件收尾。
- **第十二只眼会通知所有人**：所有持绑定终端的在线玩家收到一行不指名的记录与通知，只说「末地那边动了一下」，不给坐标与攻略。
- **结算之后不再发终端**：`FinaleRuntimePolicy.concluded` 之后零号站改为一行说明，已持有终端的老玩家不受影响。

## 两种结局与本地锁

### 成功

- 崩塌达 100% 前击败世界接口。
- 恢复终端托管、资源包与窗口状态，完成成功诗篇、名单、片尾与原版返程；**成功配乐在资源包恢复前释放**。
- 建立持久成功锁，实际回到主世界后解锁视距。
- 本地成功存档显示「存档已封存」并禁止进入。

### 失败

- 崩塌先达 100%，世界接口进入**逃逸演出**：在废墟上悬停 30 Tick，随后垂直升空（55 Tick 内加速到每 Tick 3.4 格），音量随高度衰减、音调随高度上扬；170 Tick 结算窗口结束时它已在数百格之上。它没有被打退，只是不再看着这里。
- 单人或远程客户端完成 Windows／后备演出后**不再关闭游戏**：原版回程送回主世界，缺失材质渲染与 actionbar 接管收尾。
- 已发布 LAN 的房主保持服务器运行并返回主世界；**只在房主本地**呈现缺失材质，LAN 客人不受影响。
- 失败者可从暂停菜单返回主菜单；重启后保留 Alpha 呈现直到 F8 恢复完成。
- 本地失败存档显示「存档已损坏」并禁止进入。

### 结局锁

**身份立刻写，窗口快照事后补。** 成功路径先写一次不带快照的身份锁，资源包恢复回调里再补一次带快照的；幂等判定额外要求「要求带快照时快照必须已存在」。失败路径在同一 Tick 里撤窗口并上锁。

**锁只封存打这一局的那个世界**（锁格式 v3 → v4，新增 `serverAddress`；v1–v3 仍可读，只是封存得更少）：

| 这一局打在哪 | 封存什么 | 不受影响 |
| --- | --- | --- |
| 本地存档 | 该存档（存档列表 + 打开流程，显示「已封存 / 已损坏」） | 其他单人存档、所有服务器 |
| 远程服务器 | 该服务器地址（连接时拦下并说明原因） | 其他服务器、所有单人存档 |
| 桌面 Meta 尚未回滚 | 标题页三个入口一起禁用，提示按 F8 恢复 | —— |

设置、辅助功能与退出永远可用。从结算开始，普通异象、空档补压、衰减与个人追逐永久关闭，不会在 `COMPLETE` 阶段重新出现。

## F8 恢复与重新游玩

- **没有结局锁时 F8 不做任何事**，也不切换 Meta。
- 有结局锁时按成功／失败打开对应文案的确认框；确认后恢复 MOD 持有的桌面、记事本、窗口、资源包与演出状态，再正常关闭。
- 失败演出写入的记事本正文第二段就说明这一步；该窗口按普通尺寸打开，不最大化，以免挡住它所写的失败壁纸。
- 检测到 Wallpaper Engine（仅 `wallpaper32.exe` / `wallpaper64.exe`）时先 `-control stop` 暂停播放，路径写入事务清单，F8 时 `-control play` 恢复。MOD 不结束该进程，也不启动玩家自己关掉的它；此步失败只降级为「桌面保持原样」。
- 重启后精确对应的本地结局存档只增加 `.thefourthfrequency-corrupted` 无损标记。
- MOD **不修改** `level.dat`、区块或玩家数据；重新游玩需要新建世界。
- 结局事务中断时用 `-Dthefourthfrequency.safeMode=true` 启动一次执行安全恢复。

## 多人特效与 HUD（RC.2）

三类自定义风暴粒子按空间单元和 tick 批量发送，同维度附近队友共享样本；服务端和客户端均有独立预算，低粒子设置会减少装饰密度，主要激光几何和伤害不依赖装饰粒子。完整边界与多人回归见[多人体验验收](../qa/multiplayer_experience/README.md)。

HUD 使用紧凑布局，标题、百分比、倒计时、锚点提示和灯条按字体实测宽度分别分配区域。较长翻译使用省略号，底部保留内边距；锚点破坏提示不会再挤进倒计时，扣血闪光只由新伤害触发。
