# 音频与背景音乐

`MusicDirector` 通过 `MinecraftMusicMixin` 接管原版的两个接缝：`getSituationalMusic` 决定放什么，`getMusicVolume` 决定淡入淡出的目标增益。调度、淡变与「正在播放」提示全部沿用原版实现。

本文记录音效输出增益与配乐；音效的混音余量见[世界接口终局](world-interface.md)，客户端生命周期见[架构与安全边界](architecture.md)，取舍见[设计札记](design-notes.md#背景音乐)。

## 音效输出增益（RC.5）

`ModOutputMix` 在客户端最终通道增益处放大本 MOD 的主体音效；初次播放、持续更新与分类刷新使用同一策略，每次仅应用一次。主体音效乘 1.8，`terminal_*` 轻提示（不含载波）乘 1.25；`music_*`、信号底噪、未渲染层环境床和 `world_interface_ambient_*` 不增加。原版与其他 MOD 的声音不变。

`meta.peakVolume` 仍是 0–1 的 MOD 总音量控制，并非新增放大滑块。输出增益限制在 0–1，原本接近上限的声音提升较少；零音量仍静音。保留原始发声音量与服务端包，所以不会扩大传播半径，多人各客户端独立混音。主体音效未触及上限时约提高 5.1 dB，终端约提高 1.9 dB；音乐沿用下述规则。

终端拖动只保留限频的轻刻度声，不再叠加循环扫频；进入锁定频段时，锁定提示替代当次刻度声。自动引导弹字保持无声。终端载波与环境底噪恢复初版，9 份文件逐字节保留且不参与放大，来源与哈希见 `docs/art/audio/original_beds.json`。其余新制作音效移除持续白噪底层，接触材质改为离散共振短声，激光束流改用调制音调；初版开屏卡机基底保留。待试听的录音素材激光/触手样板未替换进游戏。验证见 [RC.5 记录](../qa/audio_overhaul/rc5.md)。


追逐前的“终端传来剧烈震动”提示使用初版 `terminal_anomaly`，来源与原始哈希见 `docs/art/audio/original_cues.json`；自动引导文字保持无声。

## 情境判定

**自上而下取第一条命中的情境。**

| 情境 | 结果 |
| --- | --- |
| 追逐战镜像世界（黑屏与加载界面期间即已开始） | `music_pursuit`（1 首，循环） |
| 追逐战其余阶段（预警、捕获、逃脱结算、返程） | 静音 |
| 踏入终局传送门之后（含终末之诗、名单与片尾） | 胜利 `music_ending` / 失败 `music_ending_failure`（各 1 首，循环） |
| 世界接口召唤与第一阶段 | `music_encounter_phase_1`（1 首，循环）；**从召唤的第一 Tick 起**。召唤与第一形态共用同一首，中间没有换曲 |
| 世界接口第二阶段 | `music_encounter_phase_2`（1 首，循环） |
| 世界接口第三阶段 | `music_encounter_final`（1 首，循环） |
| 两种结算与传送门开启 | 静音 |
| 加载与过渡界面（`LevelLoadingScreen` / `ProgressScreen` / `GenericMessageScreen` / `ConnectScreen` / 任何 Overlay） | 静音 |
| 主菜单／无玩家 | `music_menu`（4 首），但要等安全告知放行 |
| 安全告知尚未放行 | 静音 |
| 其他带音乐标记的 Boss 血条（末影龙、凋灵） | 静音 |
| 末地，且世界接口尚未召唤（`UNPREPARED` / `ARENA_READY` / `WAITING_TERMINALS`，或快照尚未到达） | `music_end`（1 首，循环） |
| 常规游戏 | `music_game`（9 首，间隔 4800 Tick／4 分钟，仍受音乐频率选项约束） |
| 未渲染层，且细菌已在本次会话里出现过（`UnrenderedLayerClient.hunted()`，一旦为真就锁住） | `music_unrendered`（1 首，循环），淡变目标再乘 `UNRENDERED_MUSIC_TRIM = 0.45` |
| 未渲染层，细菌还没出现 | 静音：进层的第一分钟是这地方在说明自己是空的，配乐跟着玩家一起到就等于说它不是 |

**「放行」取的是按下「我已知晓」那一刻**，而不是 `FirstRunNoticeController.acknowledge()`（后者要等屏幕跑完 28 Tick 的退场动画）。同一次入场还会把 `nextSongDelay` 清零。

**末地那一首的判据取维度而不是阶段**：世界接口的快照随世界下发，玩家在它到达之前就已经站在末地了，所以「没有阶段」也算未召唤。`COMPLETE` 被排除在外。

## MOD 总音量

`meta.peakVolume` 是本 MOD 的**总音量**，配乐也在其中：`musicVolume` 把原版给出的淡变目标乘上它再返回，缓存的 `fadeTarget` 存的也是乘完之后的值。

入口有两个：`config/thefourthfrequency.json`，以及首启开屏的**音量校准页**。滑条拖动时只改进程内的那份配置，所以旁边的「试听」立刻就是新电平。试听播放 `terminal_boot_complete` 干净完成提示；重复点击会替换上一段试听。

## 四条淡变规则

### 1. 进入世界时的菜单曲淡出

**唯一一次在跟别的东西赛跑的淡出**，所以不走原版曲线，而是 **10 Tick（0.5 秒）的线性斜坡**。

- 斜坡每 Tick 由记下的起点**重新算出**（而不是逐 Tick 累乘），所以原版在同一 Tick 里对同一个值做的缓动无法把它带偏。
- 走完斜坡会主动 `stopPlaying()`：此时已经听不见，但要把音轨真正交还。
- 加载结束的边沿仍保留一次 `stopPlaying()` 兜底，应付短到连 0.5 秒斜坡都装不下的加载。
- **追逐战豁免这两条**，因为黑屏底下盖着的正是镜像维度的切换，而追逐曲此时正在淡入。

### 2. 打完之后退出到主界面：配乐跟着玩家走

**唯一一次配乐要跨过世界卸载继续播。** 状态机是纯类 `client_ui.EndingScoreHandoff`（main，可直接单测）：

| 状态 | 进入条件 | 效果 |
|---|---|---|
| `OFF` | 默认 | 一切照常：菜单曲拥有标题画面，加载界面静音 |
| `ARMED` | 结局已确认**且玩家已回到世界**且不在加载 | 加载空档按常规游戏曲计分、跳过入世淡出与加载兜底；断线时保住音乐通道 |
| `HOLDING` | 无世界且无加载界面（已落在标题画面） | 标题画面继续由 `music_game` 计分，菜单曲不接管 |
| 回到 `OFF` | 再次进入任何加载或世界 | 恢复常规，入世淡出照走 |

三个约束缺一不可：

1. **不能在诗篇确认那一刻就 `ARMED`**——胜局清理会恢复资源包，那是一次完整资源重载并挂出加载遮罩。
2. **必须早于退出就 `ARMED`**——`Minecraft#disconnect` 内部直接把世界拆掉，声音在同一次调用里全停。
3. **必须绕过引擎的整体停止**——`updateLevelInEngines` 里那句 `soundManager.stop()` 会清空所有通道。

**失败结局不参与**：它的 `scoredOutcome` 闩存本来就不释放。

### 3. 战斗曲交接（约 3 秒）

其余每次换曲中间都隔着一段刻意的静默（原版曲线：目标增益降 0，旧曲约 15 秒淡出，新曲约 10 秒淡入）。BOSS 战是唯一例外，`MusicDirector` 用同样的两条曲线、但陡得多地自己接管：

| 步 | 做法 |
|---|---|
| 淡出 | `situationalMusic` 在交接期间返回 null，同时每 Tick 在原版 0.97 的衰减之上再乘 **0.80**，约 1.5 秒清空声道 |
| 起播 | 把 `nextSongDelay` 清零（每次停止都会给它加 100 Tick，「持续」选项还会把间隔锁死在 100 Tick） |
| 淡入 | 每 Tick 额外跑 **7 次**原版的淡入步进，约 1.2 秒回到目标增益 |

> **三个 `music_encounter*` 事件的 `replaceCurrentMusic` 必须为假。** 该标志在音乐管理器自己的 tick 里判定，早于本类看到这一帧，留着它就会在交接开始前先把旧曲切掉。其余曲目仍是 0 延迟 + 即时顶替。

### 4. 起音必须从静默开始

`MusicManagerGainAccessor` 在「没有曲子在播、但马上要有」的边沿把增益压到 0。该写入以 `currentMusic == null` 为前提，避免情境抖动一帧就掐断正在淡出的曲子。

`silenceGain` 把增益**和分类音量一起**归零。

**硬切点只有两处**：追逐黑屏与被捕获——那里的设定是信号被切断。

## 曲目轮换：放完一轮才会重复

Minecraft 没有播放列表。`sounds.json` 里一个事件带多条 `sounds` 是一个**加权随机池**，每次播放独立抽取。

| 项 | 规则 |
|---|---|
| 参与轮换的事件 | 只有 `music_game`（9 首）与 `music_menu`（4 首）。单曲事件与攻击音效变体自动排除 |
| 规则声明 | `audio/MusicRotationPolicy` |
| 执行点 | `AbstractSoundInstanceRotationMixin` 挂在 `AbstractSoundInstance#resolve` 上 |
| 一轮结束的判定 | `MusicRotationPolicy.passComplete(事件, 池大小)` **数**本轮已用曲目数，不是靠重抽失败推断 |
| 池大小来源 | `WeighedSoundEventsPoolAccessor` 从 `WeighedSoundEvents` 私有的 `list` 读出（`getWeight` 是权重之和，不能当计数用） |
| 命中重复时 | **重新抽取**而不是按下标挑一个，以免抹平原版权重。上限每首 32 次（十首池 320 次，接缝处 32 次） |
| 轮次接缝 | 新一轮的第一首不能是上一轮的最后一首 |

> **轮换逻辑不能挂在 `WeighedSoundEvents` 上**——它不记录自己的事件 id，挂在那里就分不清配乐和那八条本来就该自由抽取的攻击音效。

`MusicRotationPolicyTest` 双向校验声明清单与 `sounds.json` 的实际池大小，所以新增一首曲子却忘了它会是测试失败。

## 常规游戏曲的间隔

`music_game` 用 `Music(holder, 4800, 7200, false)` 而不是原版的 `Musics.createGameMusic`（10–20 分钟）。

**真正决定间隔的只有下界**：管理器每 Tick 都重新在这个区间取一次随机数并与当前值取最小，包括曲子播放期间的那几千 Tick，所以上界基本只是意图声明。

当前周期约 6 分 10 秒，可闻占比约三分之一（九首平均 2 分 10 秒）。

玩家的音乐频率选项仍然有效：「频繁」的上限是 12000 Tick，高于 4800，因此不产生影响；「持续」在管理器里被硬编码为 100 Tick，会覆盖任何曲目自带的节奏。

## 未渲染层的四条音频

四条全部由客户端按维度自行判断播放与停止，**不需要任何协议**。

| 声源 | 通道 | 音量 / 半径 | 说明 |
|---|---|---|---|
| `music/unrendered/nice_boys.ogg` | `MUSIC` | 入库 **−23 LUFS**，播放再乘 **0.45** | **这一层曾经刻意不放配乐**（`select` 直接返回 null），理由是「从没为任何人配过乐的地方不该听起来像被配过乐」。现在放的不是为这层写的曲子，而是从常规游戏轮换里搬过来的那一首：玩家认得它，而认得它的地方不该是这里。**它是细菌的配乐而不是房间的**，所以等实体出现才起播；也压在底噪与心跳之下，因为那两条才是玩家用来判断位置的信息 |
| `layer_ambience.ogg`（20 秒循环） | `AMBIENT` | 播放音量 0.11 | 原创合成环境底噪，解码测量见 soundscape_manifest.json |
| `heartbeat.ogg`（1 秒） | `HOSTILE` | 按距离 0.35→1.0 | 定位在细菌身上，64 格半径，每 30→7 Tick 一次；近场足音单独播放 |
| `capture_scream.ogg` | UI | 捕获转场 | 私人单次音效跨返回传送继续播放；测量见 soundscape_manifest.json |

## 末地的雷

雷声借用原版 `LIGHTNING_BOLT_THUNDER`，由客户端按世界时钟排程后本地播放（调度规则见[世界接口终局](world-interface.md#末地的雨)）。

- **走 `SoundSource.WEATHER`**，不是 `AMBIENT` 也不是 `HOSTILE`。`silent_world` 静掉的是 MUSIC / AMBIENT / HOSTILE，所以雷声会穿透那个异象——**刻意与原版雨声保持一致**。
- **原版这条 cue 自己不声明衰减距离**，所以按 16 格淡尽，而雷是从玩家上方 64 格、外侧 96 格处发出的。它按 `AudioService.playWithReach` 的同一套换算走。
- **音量仍受 `peakVolume` 约束**，配置调到 0 时一声不响。它**不走** `ENCOUNTER_MIX_TRIM`——那条 trim 是给遭遇战的授权 cue 用的，而这是天气。

## 素材入库：先对齐响度，再衰减

以 44.1 kHz 立体声 Ogg Vorbis（q4）随模组分发，播放电平由 `tools/import_music.py` 在导入时**烘焙进文件**，而不是写在 `sounds.json` 里。**两步，顺序不能反：**

1. **对齐响度**：每首母带用 ffmpeg 的 `loudnorm` 实测积分响度，再用一次**纯线性增益**平移到 **−24 LUFS**。母带跨度是 −3.6 到 −16.4 LUFS。
2. **再衰减**：对齐后的电平乘一个比例——默认 **0.8（−20%）**，按源文件夹可覆盖（`GAIN_BY_DIRECTORY`）。

**BOSS 战那三首走自己的一档目标：`ENCOUNTER_LOUDNESS_TARGET_LUFS = −17.0`，且不再衰减（比例 1.0）。** 上面那 −24 的推理是对着「独自响在静默里的配乐」写的，遭遇战偏偏不是：接口同时在扔八种授权攻击 cue、冲击波和原版爆炸，而配乐是玩家判断自己在打第几形态的依据。和其余曲目同档时，实测反馈就是「战斗里听不见音乐」。源文件夹原本写着「音量降低10%」的备注，也照办过；用户在 2026-08-29 去掉了那个备注并要求放大，所以文件夹现在就叫 `BOSS战`，这条常量取代了那张便条。

**这个数字调了三轮**：−20 太小，−15 过头，−17 是用户自己叫停的那一档。余量不是约束：三首母带 −3.56 / −7.00 / −11.26 LUFS、真峰约 +0.5 dBFS，落到 −17 之后真峰是 −13.0 / −9.5 / −5.4 dBFS。

**未渲染层那一首同理，走 `UNRENDERED_LOUDNESS_TARGET_LUFS = −23.0`、比例 1.0。** 这是全项目唯一一处配乐要跟本 MOD 自己的声音抢：别处的对手是原版环境音和信号床（按构造在 −24 dBFS 峰值附近），而这一层里唯一的另一个声源是 `unrendered/layer_ambience.ogg`——它按 −20.1 LUFS 入库，因为它要独自撑住六分钟。按默认档落到 −26 就意味着整首曲子躲在那条底噪后面，正是遭遇战踩过的那个坑。取比底噪低 3 dB 而不是持平：房间仍然归底噪，配乐是那个不该在场的东西。**入库电平之外还有一层播放侧的 `UNRENDERED_MUSIC_TRIM = 0.45`**，混音写在播放旁边而不是烘进文件，与环境床同一套做法。

平移只是增益，**没有压缩、没有限峰**，所以没有任何一首曲子的动态被改动。之所以可以无人值守地跑，是因为每一首母带都比目标响——增益全为负值。

实测入库结果：默认组 −26.10 ~ −25.80 LUFS；未渲染层那一首 −23 LUFS（真峰 −12.5 dBFS）；**BOSS 组现在是 −17 LUFS 一档，比其余曲目高约 8.9 dB**。

### 目标为什么是 −24 而不是原版那一档

**这 4 dB 的余量买的是本片配乐缺的动态，不是它太响。** 原版曲目的短时最大值比自己的积分响度高 **4 ~ 6 dB**——它们大部分时间待在中间的安静段落里；本片这套不是：短时最大值只高 **0.8 ~ 1.9 dB**，`game/hi` 的 LRA 只有 **1.9 LU**，`game/tenshi` 2.9、`encounter/especially_you` 3.3，全都低于原版 60 首里最低的 `broken_clocks`（4.2）。

**没有安静段落的曲子，整段播放期间听到的就是它的积分响度**，所以把这个数字对齐到原版的中位（−16.4 LUFS）会让它实际成为混音里最响的东西。落在 −24 之后，全集贴着玩家最熟的 C418 那批（−26.6 ~ −27.8 LUFS）。

比例始终相对无损母带，响度目标也始终相对母带的实测值，**所以重新导入不会叠加**。详见[美术与资产管线](art-pipeline.md)。

### RC.3 音效重置

全套 96 个非音乐事件、242 个 Ogg Vorbis 文件由 `tools/generate_soundscape.py` 生成；没有引入第三方录音。`tools/audio_materials.py` 提供共振腔、颗粒摩擦、结构撞击、故障缓冲和广播材质。七个旧音频生成/重制脚本已移除，避免重新覆盖资产。

音乐曲目与既有 BGM 音量保持不变。9 份初版底噪保留原始电平，其余音效解码后的峰值、真峰与 RMS 以 `soundscape_manifest.json` 为准；播放侧增益见本文 RC.5 节。峰值不等同于整体听感响度。

所有实际编码文件均重新解码，验证 Vorbis、44.1 kHz、时长、有限数值、直流偏移、四倍过采样真峰值和循环接缝。准确测量与 SHA-256 见 [完整声音清单](../art/audio/soundscape_manifest.json)。旧录音的 LUFS 不再描述本轮资产。

- 激光蓄力 90 Tick（4.5 秒），持续释放 40 Tick；声音跟随模型主嘴挂点，取消、离场、死亡、切世界及断线停止。双束共用一次发射的主体声音，命中点独立发声。
- 触手预警、击地和回收分别在服务端真实攻击阶段触发；装饰撞击按声音/空间网格限频，每世界每 Tick 最多 16 个，关键预警和落地绕过装饰预算。
- 返工体和细菌足音使用与渲染相同的行走周期；只处理最近 16 个装饰实体，每客户端每 Tick 最多 6 个足音/呼吸。细菌足音限 18 格，原有 64 格心跳仍承担远距离定位。
