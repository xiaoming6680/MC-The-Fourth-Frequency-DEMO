## 验证方法与结果

- `gradlew unitTest`：840 项通过，0 跳过。覆盖真实模型烘焙、重复取样不积累偏移、骨架/几何一致性、嘴部位置、触手伤害时序、UV/材质、旧存档迁移。
- `gradlew runGameTest`：94 项服务端测试通过，覆盖追逐、BOSS 攻击、存档、终端与多人隔离等行为。
- `gradlew runClientGameTest -PtffClientTestSuite=rework-forms`：三形态正面、背面及暗处共 9 张实体截图。
- `-PtffClientTestSuite=watcher-model`：正面、侧面、背面和暗处近景 4 张截图。
- `-PtffClientTestSuite=horror-entities`：HIM、Bacteria、能量球的时间取样，以及稳定锚真实崩解，共 14 张截图。
- `-PtffClientTestSuite=terminal-3d`：六状态、左右手等 15 张画面；完成实际初次终端引导。
- `-PtffClientTestSuite=world-interface`：三形态多角度、两次变身的多个时刻、全部攻击、激光释放与三次触手伤害关键帧、两种分辨率，以及成功/失败与传送流程。

实体截图测试先走完首次终端引导，再验证实体已同步、可见且位于取景方向。旧样例只判断截图调用成功，可能把终端界面当作模型验收；现已修正。BOSS 动作样例按实际客户端动作时钟取帧，而不是固定等待几帧后随意截图。

竞技场首次生成样例会清除同一测试世界中前一个伤害样例遗留的稳定锚、准备标记和缓存，再调用真实生成流程；十个稳定锚必须全部重新出现。修复了测试批次顺序导致的偶发失败，未放宽实体存在断言。

原生 Blockbench 工程包含 34 个运行时动作样本。编辑器导入现在拒绝缺失骨骼的轨道，避免动画静默丢失。
