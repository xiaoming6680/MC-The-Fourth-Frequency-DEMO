## 网络与图形边界

- 每个玩家同一 tick 的终端输入照常按序处理；第一份反馈即时发送，其余合并为后续 tick 的最终快照。限额不跨玩家共享。
- 风暴协议每包最多 256 条，拒绝非法类型、数量、非有限浮点数和越界长度。坐标采用单元原点加局部浮点偏移，世界边界仍保留小数精度。
- 每世界每 tick 最多排队 4096 个实际粒子，所有队列在 tick 末或服务器停止时清空。附近同维度玩家接收；不支持批量通道的客户端回退到原版粒子包。
- 每客户端每 tick 最多处理 2048 个粒子候选；“减少”显示一半，“最少”显示四分之一。真实客户端两次超量提交验证“最少”最多生成 512 个。主要光束几何与伤害判定不走这条装饰粒子预算。
- 跨维度旧粒子包直接丢弃，断线清空计数；客户端缓存只保存维度标识，不保留旧世界对象。
- 结构缓存减少重复定位，不会把原版世界生成改成异步；首次未缓存的结构定位仍可能造成停顿。

首次问答的输入格式已改变，联机双方须使用同一 RC.2 构建。存档中的个人答案和三阶段迁移格式保持兼容。BOSS 正式名单仍为最多 8 人；这不是对超大服务器或任意整合包的性能认证。

## 测试证据

最终 `gradlew build` 通过：**851 个单元测试全部通过、0 跳过；97 个服务端 GameTests 全部通过**。`tools-ui`、`mainline`、`world-interface` 三套实际客户端测试均通过。完整日志保存在 `build/experience-*.log`，完整客户端截图在 `build/qa/`。

RC.2 成品与 PCL 部署文件 SHA-256 一致：`79c22d7c46213c75b74ad1f99c08b2e8a128ea079929c27860e509770ffdd125`。成品检查覆盖 58 个 Mixin 类、21 个 Minecraft 注入目标。PCL mods 目录仅保留 RC.2；已验证的旧 RC.1 移到忽略的构建备份目录，避免重复加载。

修正的客户端样例：初始文件目录按实际解锁工具包含说明书，不再硬编码只有两份文件；下界导航测试建立安全落点并等待加载界面真正关闭，再验证私人异象、终端和返回点。原先的熔岩死亡与加载画面截图不会被当作功能验收。

可复现命令（游戏 runner 共享清理目录，必须串行）：

```text
gradlew.bat runClientGameTest -PtffClientTestSuite=tools-ui
gradlew.bat runClientGameTest -PtffClientTestSuite=world-interface
gradlew.bat runClientGameTest -PtffClientTestSuite=mainline
gradlew.bat build
```

服务端多人样例使用同一真实 GameTest 服务器中的多个模拟 ServerPlayer；客户端验证使用真实 Minecraft 客户端与集成服务器。尚未进行多台电脑经公网连接的延迟/丢包压测、长时间多人实战或全硬件帧率认证。自动化通过也不等于 AAA 观感已经获得人工验收。
