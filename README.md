# The Fourth Frequency · 第四频段

[English](README.en.md) · **中文**

面向 Minecraft 1.21.11 的 Fabric 生存恐怖叙事模组。

玩家在唯一的零号站醒来，得到一台会提供真实生存信息的旧终端。它不靠凭空加入怪物制造恐怖，而是让你熟悉的方块、菜单、声音和规则逐步失去原有解释——终端是你唯一稳定的解释工具，而它也在被同一件事影响。

> 当前构建版本 **1.0.0-rc.4**，包含 BOSS 动作同步修复、安静终端反馈与卡机开屏音效。客户端与服务端请使用同一构建；仍处于发布候选阶段。

## 运行环境

| 组件 | 版本 |
|---|---|
| Minecraft | 1.21.11 |
| Fabric Loader | 0.19.3 或更高的兼容版本 |
| Fabric API | 0.141.4+1.21.11 |
| Java | 21 |

客户端与服务器都需要安装本模组和 Fabric API。许可证：[All Rights Reserved](LICENSE)。

## 安装

1. 按下面的步骤构建 `thefourthfrequency-1.0.0-rc.4.jar`。正式发布的附件以 [Releases](https://github.com/xiaoming6680/MC-The-Fourth-Frequency-DEMO/releases) 为准。
2. 与对应版本的 Fabric API 一起放入客户端和服务器的 `mods` 目录。
3. 用 Java 21 启动 Fabric 1.21.11，**新建世界**或连入服务器。

从源码构建（Windows 用 `gradlew.bat`，Linux/macOS 用 `./gradlew`；需要 JDK 21，其余依赖由 Gradle 自行拉取）：

```powershell
.\gradlew.bat clean build --no-daemon
```

产物输出到 `build/libs/`。构建的最后一步可以把 JAR 复制进一个本地 Minecraft 实例，**默认关闭**；在用户级 `~/.gradle/gradle.properties` 里写 `tffDeployDir=<路径>` 长期启用，或用 `-PtffDeployDir=<路径>` 临时指定。更多命令见[测试与验收](docs/zh/testing.md)。

## 玩法概览

### 主线与终端

首次进入世界时，零号站按固定 Tick 预算在出生点附近建造：先选一块平整、不临水、不含方块实体的地面，再自下而上补齐地基、地板、墙体与屋顶。站体自带照明，室内不刷怪，也没有战利品。世界重生点同时设在站心。

每位玩家只获得一台有效的个人终端。**发到手的那一刻它会自己开一次**，之后手持右键打开私人界面，不暂停游戏，也不写入聊天。它是一台封死的双手仪器——黑铸铁机身、黄铜边条、左侧大 CRT、右侧示波器与罗盘；打开时相机凑近屏幕，而不是设备翻开。

| 页面 | 内容 |
|---|---|
| `HOME` | 当前服务端权威目标、工具建议与最近记录 |
| `TOOLS` | 住处、矿物、传送门、天气、导航、要塞六个工具，随主线逐个解锁 |
| `RECORDS` | 剧情、里程碑、文件调查与追逐预警。普通异象在记录第一次末影之眼方向之前一律不写入；此后终端一次性放出整局的异象日志，并从此继续记录 |
| `FILES` | 四份破损文件与一本需要读完它们才解锁的完整日记；若这台机器上有上一局通关记录，还会多出一份前一位持有者的残篇 |

主线沿原版生存路线推进：认识终端 → 木材 → 铁 → 下界 → 下界要塞 → 烈焰棒 → 返回主世界 → 末影之眼 → 要塞 → 末地 → 击败世界接口。任务奖励在完成的那一刻直接发放，不需要领取。

多人时，采集类任务照常按人头结算——八个人各挖各的铁，八份火把是同一笔交易。但整队只做一次的六项（进入下界、找到要塞、返回主世界、找到要塞传送门、进入末地、击败世界接口）共用同一个传送门、同一座要塞、同一个 BOSS，所以它们的奖励是**一份按在场人数均分**，最少一个。BOSS 血量按 `1 + 0.5 × (人数 - 1)` 放大，满编 4.5 倍；八份原样发放会是 8 倍，两条曲线对不上。任务卡上显示的数量始终等于实际到手的数量，完成提示也会写明是几人均分。

新档第一次打开终端时，开机自检之后、四步导览之前，终端会做一次**用户建档**：五道选择题，答案不是按钮而是右侧调谐滑块上的锁点。问题清晰，选项在噪声里，玩家要把接收机调上去才读得出来，锁定并按住约 1.75 秒（35 tick）才算作答。五题答完，LCD 只回一句「用户偏好已记录」。

建档一次性：受伤兜底、强制关闭和掉线都会就地封存，没答完的题保持「未作答」而不会被填上默认值，终端会明说建档不完整。答案只改终端如何呈现、以及在同等强度里挑哪一类，从不改数量、时机、强度或时长——它在第一分钟被问、之后再也不能重设，所以它不允许变成一个隐藏难度选项。

详见[终端界面与手持形态](docs/zh/terminal-ui.md)。

### 异象与个人追逐

18 项异象分五阶段滑动推进，从环境误差逐步走到界面与规则层；其中 2 项是持续数分钟的低强度"持续型"异象。主线只提高上限，实际阶段每次最多升一级。

异象只在主世界和下界发生。下界跑的是一份更短的间隔——主线把你送进去的那段路本身就是一次目的明确的短差，按主世界的节奏走完，世界可能全程都没有失态过。末地不触发任何异象：那是终局自己的舞台。进末地时等待计时会冻结，回来时从冻结处接着走，既不会一落地就来一发，也不会白白损失一整段。

阶段 5 的**未渲染层**是唯一一项把你搬出所在世界的异象：地板让开，一秒黑屏，人落在一片程序生成的无尽室内平面里。走一分钟之后，视距之外会多出一样东西，它比你疾跑略快、比你疾跑跳慢，此后只做一件事。出去的路是一面颜色微微不对、并且拦不住你的墙——穿过去，你会掉在自己世界的天上。

校正者有寻声者、定向者、截断者、越界者、接口校正者五个个人形态。异象会安全演示形态的规则，但这不是前置——第一次遇见就可能是正式追逐，解释在事后到达。正式追逐把玩家送入对应维度的**私人镜像**：地形按玩家所在区块持续流式复制，其他玩家、实体、物品与恢复账本完全隔离，全服同一时刻只有一场——被带走是发生在你身上的事，不是按班次轮到你的事。

> 世界不是真的，但受到的伤害是真的。

详见[异象、终端形态与个人追逐](docs/zh/anomalies-and-pursuits.md)。

### 末地终局：世界接口

最后一颗末影之眼落进要塞门框的那一刻，终局就准备好了——不再有任何个人前置条件。战斗发生在**原生末地主岛**，只贴地布置 11×11 共振祭坛和 10 座稳定锚。

> **服主请先读这一条。** 第 12 颗眼落框会永久取代原版末地结局：出口传送门、龙蛋与末地折跃门不再生成，末影龙也无法复活。没有折跃门就到不了末地外岛，鞘翅、潜影盒和末地城因此对全服永久不可达。单人叙事不受影响（返程由本 MOD 自己的出口承担），但共享生存服应当先打完原版末影龙、拿到折跃门，再去凑第 12 颗眼。

**名单就是交出终端的那些人**，最多 8 个：手持自己的绑定终端亲手插进共振核心即加入，别人上线下线与这场仪式无关。第一台终端进核心时开始 3 分钟窗口；期间可以随时撤回，三分钟内没有人按下**召唤**，所有终端原路退回、什么也没发生。召唤只能由已经交出终端的人按下，按下即原子提交。BOSS 最大生命为 `600 × (1 + 0.5 × (人数 - 1))`，分三个只前进的形态，崩坏计时 12000 Tick（10 分钟）。稳定锚会治疗它、延长它的出手间隔，也会投射保护玩家与地形的稳定区——拆锚是一次真实的取舍，不是"先拆塔"。

**末地现在会下雨，并且时不时打雷，但没有云。** 这是纯客户端呈现：存档里的天气记录是全维度共用的，写它等于让主世界永远下雨，所以一个字节都不会被写。原版也从不认为末地在下雨——`isRaining()` 在那里仍然是假的——于是雨看得见、听得见，却不改变任何一条游戏规则。**打赢之后雨会在十秒内散掉**：那片天是它带来的，它没了，天也就不必再是那样。

详见[世界接口终局](docs/zh/world-interface.md)。

### 结局、F8 与存档

成功和失败都走原版终末之诗通道回程，只替换本次诗篇、制作人员名单与片尾，并写入本地结局锁：之后标题页只禁用单人、多人和 Realms，设置与退出始终可用。

失败会替换桌面壁纸并打开一份记事本，正文直接告诉玩家按 `F8` 撤销全部本地更改。`F8` 不是随时可用的开关——只有已记录结局时它才打开对应的重置确认。重启后本次存档以无损标记隔离（成功"已封存"、失败"已损坏"），`level.dat`、区域和玩家数据不被改写；重玩需要新建世界。

演出中断时用 `-Dthefourthfrequency.safeMode=true` 启动一次安全恢复。

## 安全边界

- 恐怖来自熟悉系统被重新解释，**不来自**无提示删档、不可恢复的剥夺或还原不掉的桌面改动。
- 仪器可以给出错误但可信的读数，但**每个谎言都会在记录页留下能被你事后抓住的痕迹**。
- 伪造的报错必须字面为真；东西可以真的被拿走，但**一定会回来**。
- 页面标签、返回、关闭、暂停菜单与安全恢复等退出路径不被演出永久夺走。
- 闪烁不超过 3 Hz；高对比与峰值音量受首次安全告知与配置约束。
- 客户端幻觉不污染服务端权威状态；LAN 房主的本地演出不影响其他玩家。

完整叙述见[世界观圣经](docs/zh/world-bible.md)。

## 配置与调试

首次启动生成 `config/thefourthfrequency.json`。总音量也可以在开屏第一页（音量校准）直接拖，不必手改文件。

| 配置项 | 默认值 | 作用 |
|---|---:|---|
| `meta.enabled` | `true` | 允许固定白名单的本地 Meta 演出 |
| `meta.peakVolume` | `0.8` | MOD 总音量：本模组的全部音效与配乐都乘它，校验到 0–1；开屏第一页的滑条写的就是这一项 |
| `pacing.developerAcceleration` | `false` | 缩短开发回归等待，不跳过真实交互 |
| `clientState.alphaDowngradeComplete` | `false` | 是否已完成首次 Alpha 降级演出 |
| `clientState.viewDistanceUnlocked` | `false` | 成功诗篇回程后是否已永久解锁视距 |
| `clientState.debugHudGroups` | 缺省即四组全开 | 调试 HUD 显示哪几组的位掩码；仅在个人调试开启时生效 |

管理员对自己执行 `/tff debug true` 后，按可重绑的 `M` 打开测试台：左栏在异象／文件／生存节点三个列表之间切换，右栏一次写完全部状态并按组给出动作。开启调试的同时，左上角出现常驻 HUD（下次异象倒计时、候选池、等级与冷却、主线与文件、追逐与终局），本模组自己的实体会被描边高亮；可重绑的 `N` 收起或展开 HUD，HUD 显示哪几组由面板里的勾选决定。所有按钮动作都由服务端核对授权、动作 ID、目标与当前上下文；`/tff debug false` 关闭。
